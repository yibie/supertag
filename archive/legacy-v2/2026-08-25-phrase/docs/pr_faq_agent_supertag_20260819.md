# PR/FAQ：让 Agent 与整个 Supertag 知识库协作

- Status: Draft for user review
- Date: 2026-08-19
- Scope: Superchat Skill、Supertag Cowork 与 Supertag 的知识读写边界
- Non-goal: 本文不启动 phase、不拆任务、不开始实现

## Press Release

### Supertag 让个人知识库成为可以持续对话的思考伙伴

**Superchat 用户可以用自然语言理解、检索和讨论整个 Supertag 知识库；只有明确说“记下来”时，Agent 才会把指定内容立即写回笔记。**

Supertag 将提供两种互补的 Agent 体验：普通 Superchat 对话可以临时加载 Supertag Skill，在日常讨论中查询知识库，或把值得保留的认识写入笔记；专用的 Supertag Cowork 则提供一个面向整个知识库的长期对话空间，用于恢复上下文、理解复杂概念、追问已有判断并继续深度思考。

两种体验都通过 Supertag 已有的 Query、概念、Semantic Tag、Schema、字段、Backlink 和 Semantic Edge 工作。Agent 不拥有知识库，也不会替用户自动决定知识结构。

### 问题

Supertag 已经可以把 Org 文件组织成结构化知识库，但用户仍需承担大量方法成本。

想写下一条内容之前，用户会先考虑放在哪里、使用什么标签、怎样建立关系。重新打开复杂笔记时，又必须在脑中恢复概念结构和术语含义，才能继续思考。未来检索时使用的语言还经常与当初记录时不同，关键词搜索很容易失败。

普通 LLM 可以回答一般知识，却不知道个人笔记当前确实记录了什么。反过来，如果允许 Agent 自动生成摘要、标签、Schema 和关系，它又会快速制造一个规模更大、更难浏览的知识库。

最终，注意力从“我正在思考什么”转移到了“我应该怎样维护笔记”。

### 解决方案

Agent 成为对话与思考伙伴，Supertag 成为长期、可检查、可编辑的个人语义知识层。

用户可以直接问：

> Ontology 的核心结构是什么？这些语义要素分别意味着什么？

Agent 自行决定何时使用模型已有知识、何时调用 Supertag Query、何时搜索外部资料。回答以综合结论为主，并引用知识库中的具体 Org 原文。笔记现实、外部来源和 Agent 推断必须可以区分。

对话默认只读。用户可以自由提出不成熟、矛盾或试探性的想法，而不用担心它们自动进入知识库。

只有收到“记下来”“更新这个判断”等明确指令时，Agent 才会立即写入。该指令本身就是写入授权，不再追加固定预览或二次确认。写入后，Agent 必须报告实际创建或修改了什么。

当写入对象明确时，Agent：

1. 创建或复用一个概念；
2. 保存用户明确要求记录的判断；
3. 自动附上当前来源链接及相关原文；
4. 报告实际写入结果；
5. 根据已有知识提出可能的 Tag、Schema、字段和语义关联建议；
6. 只有用户随后确认，才应用这些结构建议或建立 Semantic Edge。

如果“记下来”指向的内容确实无法判断，Agent 先询问缺失信息；不能把额外确认变成每次都要经过的固定流程。

### 负责人引语

> “我不想让 Agent 替我生产更多笔记。我希望它先帮助我理解自己的知识，让我能够回到原始记录中继续思考。真正值得长期留下的，是我明确决定保存的判断和独特感悟。”

### 知识如何从对话进入笔记现实

本产品借鉴 Zettelkasten 从 fleeting notes、literature/reference notes 到 permanent notes 的加工过程，但不照搬固定的笔记类型或 Roam 层级。真正需要保留的是三条边界：尚在流动的思考不是正式知识，外部材料不是个人判断，只有经过用户确认的清晰陈述才进入长期知识对话。

在 Supertag Agent 中，这个过程表现为四层：

1. **最近对话是工作记忆。** Cowork 用它恢复正在进行的思考；它可以包含试探、矛盾和未解决问题，并由下一次总结覆盖。
2. **外部来源是证据现实。** URL、作者、相关原文等回答“外部材料实际说了什么”，不能和 Agent 的解释或用户判断混为一谈。
3. **对话中的理解是候选判断。** Agent 可以解释、比较、综合并提出概念或关系，但这些内容默认仍只属于当前对话。
4. **明确保存的陈述是笔记现实。** 用户说“记下来”后，指定判断才成为正式记录；如果它来自外部材料，来源链接和相关原文同时写入，但仍分别保留身份。

“记下来”触发的是一次明确的晋升，而不是复制整段聊天。Agent 立即写入判断及可确认的来源，然后使用 Query 寻找相关概念和已有判断。查询得到的概念归属、Tag、Schema 和 Semantic Edge 仍然只是建议；只有用户再次确认，才进入正式知识结构。

参考方法论：[Implementing a Digital Zettelkasten using Block References in Roam Research with Beau Haan](https://www.youtube.com/watch?v=KoddCmn3eL0&t=113s)。其中关于[从来源加工出清晰判断](https://www.youtube.com/watch?v=KoddCmn3eL0&t=857s)、[寻找相关笔记以继续对话](https://www.youtube.com/watch?v=KoddCmn3eL0&t=1549s)和[探索式检索](https://www.youtube.com/watch?v=KoddCmn3eL0&t=2266s)的原则，直接影响本文的产品边界。

### 产品如何工作

#### 场景一：重新进入复杂主题

用户进入 Supertag Cowork，询问 Ontology 的核心结构。

Agent 查询整个知识库，读取相关概念、判断、Schema、Backlink 和已确认关系，给出综合回答，并在回答中引用具体 Org 原文。用户可以沿着回答继续追问，而不需要先重新阅读整份复杂笔记。

Supertag Cowork 面向整个知识库，不绑定当前 buffer、文件或概念。当前 buffer 可以作为可选线索，但不能决定 Session 身份或限制检索范围。

#### 场景二：凭模糊记忆找回内容

用户问：

> 我记得有一个以 Pi 为基础实现的 Agent 框架，它是什么？

Agent 将问题拆成一个或多个 Query，结合 Tag、字段、alias、正文和关系寻找候选。找到后直接回答，并引用命中的笔记原文；证据不足时明确说明，而不是把猜测伪装成笔记事实。

一次 Query 没有命中，不等于笔记中不存在。Agent 应根据同义表达、alias、Tag 和已有关系继续调整查询，再判断证据是否足够。

当用户只能描述一个模糊方向时，Agent 先给出少量高层线索，说明它们为什么可能相关。用户选择其中一条后，Agent 再逐步展开原文、来源、上下文和已确认关系。检索因此是一段可以沿线索推进的探索，而不是要求用户一开始就给出完整关键词或让 Agent 猜中唯一查询式。

#### 场景三：在普通对话中保存认识

用户在普通 Superchat 对话中形成一个判断：

> 记录工具可以替换，真正需要长期拥有的是独立于界面、模型和 Agent 的个人数据层。

用户加载 Supertag Skill 并说“记下来”。Agent 立即创建或复用相应概念，记录判断，并附上本次讨论或当前文章的来源。它可以建议关联“数字独立”“个人数据库”等已有概念，但不能自动建立关系。

普通 Superchat Session 即使加载了 Supertag Skill，也不会更新“最近一次对话总结”。

#### 场景四：回到知识库继续深度思考

用户浏览 Supertag 中细粒度的概念、判断、来源和已确认关系。Agent 生成的临时建议不会出现在正式概念页。

一个概念可以保存多条互相支持、补充或冲突的判断。新的判断不会覆盖旧判断；Agent 在回答时应呈现分歧并分别引用依据。

#### 场景五：恢复最近一次 Cowork 思路

Supertag Cowork 独占维护一份独立的“最近一次对话总结”文件。它记录当前主题、已经形成的认识、尚未解决的问题和继续入口。

该文件是工作记忆，不是正式知识。Cowork 使用新总结直接覆盖旧总结，不在该文件中保留历史版本。完整对话历史仍由 Superchat Session/Tape 保存。

### 用户引语

> “我不需要记住自己当初用了哪个标签，也不需要先把知识组织正确。我可以先提问、讨论和阅读；真正形成判断后，再明确告诉 Agent 把它留下来。”

### 如何开始

用户可以在普通 Superchat Session 中加载 Supertag Skill，或进入专用的 Supertag Cowork，与整个 Supertag 知识库开始对话。

## FAQ

### Customer FAQ

#### 1. Supertag Skill 与 Supertag Cowork 有什么区别？

Skill 是普通 Superchat Session 临时获得的能力。它适合在日常对话中查询笔记，或者把当前讨论中值得保留的内容写入 Supertag。

Cowork 是专门面向整个知识库的长期对话体验。它默认使用 Supertag 作为知识现场，适合持续检索、理解和思考。

二者共享相同的知识规则和受控读写接口，但 Session 定位不同。只有 Cowork 更新“最近一次对话总结”。

#### 2. Cowork 是否绑定当前 buffer 或概念？

不绑定。

Cowork 面向整个 Supertag 知识库，可以跨文件和概念查询。当前 buffer 可以作为可选上下文，但不能决定 Session 身份，也不能限制检索范围。

#### 3. 我还需要手工维护未来可能使用的关键词吗？

不应需要为未来检索预先猜关键词。Agent 应使用自然语言问题、alias、Schema、关系和多轮 Query 寻找候选。

#### 4. 回答会不会把模型知识冒充成我的笔记？

不应该。引用个人笔记时必须指向具体 Org 原文。外部知识和 Agent 推断需要与笔记内容区分。

#### 5. Agent 会不会把试探性想法保存下来？

不会。只有明确的写入指令才会改变正式知识库。

#### 6. 说“记下来”以后还要确认一次吗？

不要。“记下来”本身就是授权，Agent 应立即写入并报告结果。只有写入对象确实不明确时才询问缺失信息。

#### 7. Agent 会自动整理关系或修改 Schema 吗？

不会。Tag、Schema、字段、关系类型和 Semantic Edge 都只能建议。未经确认的建议不会进入正式知识库。

#### 8. 我可以继续直接编辑 Org 文件吗？

可以。Org 文件仍然是人可以直接浏览、编辑和迁移的长期记录。Agent 是新的交互入口，不取代 Org。

#### 9. 一个概念只能有一个正确结论吗？

不是。概念是稳定的知识主题，可以拥有多条判断。不同判断可以互相支持、补充或冲突，并分别保留来源。

经用户确认的“当前定义”可以帮助进入概念，但不会覆盖历史判断或消除分歧。

### Internal FAQ

#### 10. 什么是“笔记现实”？

笔记现实包括：

- Org 文档中真实存在的标题、正文、判断、引用和链接；
- Supertag 中真实存在的 Semantic Tag、Schema、字段值和 Semantic Edge。

模型已有知识、外部搜索结果、候选关联和 Agent 推断都不自动属于笔记现实。

#### 11. Agent 如何查询知识库？

Agent 使用 Supertag 已有的 Query 语法，而不是直接读取底层 Store。

它可以组合 Tag、字段、正文关键词、日期和已有关系，执行一个或多个查询，再读取命中节点的原文与语义信息。

Query 是 Agent 的逻辑接口。默认不向用户展示生成的表达式；需要检查检索过程时可以展开。

#### 12. 为什么先使用 Query Skill，而不是建设向量数据库？

当前 LLM 已能拆分问题、生成同义表达、使用 alias 并进行多轮查询。第一步应先验证 Agent 能否通过现有 Query、Node 和 Relation 接口完成真实工作，而不是预先建设另一套索引系统。

只有真实使用出现稳定、可复现的检索失败时，才重新评估可重建的语义检索 Projection。

#### 13. Skill 与工具能力如何分工？

Skill 负责告诉 Agent 何时查询、如何引用、如何区分来源以及哪些写入需要用户授权。Skill 本身不能扩大工具面或写入权限。

查询、节点读取和写入操作由 Supertag 接口提供；工具调用继续经过 Superchat 的 Authority 边界。

#### 14. 为什么不把 Agent 直接内置在 Supertag 中？

Supertag 擅长拥有和组织知识事实；Superchat 擅长 Session、模型调用、Skill、工具、Authority 和持续对话。

将两者分开，可以替换模型和交互层，同时保持知识数据与语义结构不变。

#### 15. 如何区分外部观点、个人感悟和共同结论？

每条判断应保留来源身份：

- 外部观点；
- 用户自己的感悟；
- 用户与 Agent 讨论后明确保存的共同结论。

判断原文、引用原文和来源链接属于 Org 文档事实；类型化的来源信息可以利用 Supertag Schema 与字段表达。动态视图可以显示轻量标签，而无需把复杂元数据铺在正文里。

#### 16. 来源链接为什么可以自动建立，而语义关系不可以？

当前文章、网页或对话是可确认的来源事实。Agent 可以在写入判断时自动附上对应链接和原文。

“支持、反驳、扩展、依赖”等语义关系包含解释和判断，因此只能建议，用户确认后才建立 Semantic Edge。

#### 17. “最近一次对话总结”为什么不属于正式笔记？

它的作用是恢复 Cowork 的当前思考状态，而不是声明某个概念已经成立。它可以包含未解决问题和下一步入口，因此必须与正式知识分开。

只有 Cowork 可以自动覆盖这份文件；普通 Superchat Session 和 Supertag Skill 不修改它。

#### 18. Agent 在知识加工过程中究竟替用户做什么？

Agent 接手不需要由用户亲自判断的机械工作：识别当前来源、保存相关原文、把自然语言问题转换为多轮 Query、找回上下文，以及提出可能的概念和关系。

Agent 不替用户决定哪条候选理解应成为长期判断，也不替用户确认语义关系。用户的“记下来”决定内容是否进入笔记现实；后续确认决定建议是否进入正式知识结构。

这保留了 Zettelkasten 方法中真正有价值的理解和选择过程，同时避免照搬其耗时的人工整理仪式。

#### 19. 为什么不照搬 Roam 的页面、嵌套和 Block Reference 结构？

视频中的具体结构服务于 Roam 的能力边界。Supertag 已经拥有稳定节点、Tag、Schema、字段、Backlink、Semantic Edge 和 Query，不需要建立平行的物理层级。

原始 Org 节点保持唯一；不同问题下的聚类、相关笔记和提纲由 Query 动态投影。Agent 在综合回答中引用原始节点，而不是为了新的上下文复制一份内容。

#### 20. 当前不做什么？

本阶段不包含：

- 全部个人数据的统一采集；
- 健康、位置、日记等生活数据仓库；
- Agent 自动整理整个知识库；
- 自动创建 Tag、Schema、字段、关系类型或 Semantic Edge；
- 专用向量数据库或内置 RAG 系统；
- 绑定单个 buffer 或概念的 Cowork；
- 新建另一套 Agent Runtime。

#### 21. 如何验证产品是否真的解决问题？

最小验证路径包括：

1. 用户用自然语言询问一个跨文件知识问题，Agent 通过一个或多个 Query 找到候选，综合回答并引用准确 Org 原文；
2. 用户在普通 Superchat Session 中加载 Supertag Skill，说“记下来”，Agent 立即创建或复用概念，写入指定判断和来源，并且不修改语义关系；
3. 用户进入 Supertag Cowork，连续讨论多个概念，检索范围保持为整个知识库而不是当前 buffer；
4. Cowork 自动覆盖更新独立的“最近一次对话总结”，普通 Skill 不更新它；
5. 没有明确写入指令时，正式笔记、Schema 和 Semantic Edge 保持不变；
6. Agent 对 Tag、Schema、字段和关系的任何新结构都只给建议，只有用户确认后才应用；
7. 用户只提供模糊线索时，Agent 可以通过多轮 Query 逐步展开候选、原文和上下文，而不要求预先存在完整关键词；
8. 用户说“记下来”后，Agent 先完成判断与来源的写入，再返回尚未应用的关联建议。

## Approved Product Decisions Pending Document Review

1. Agent 是对话与思考伙伴；Supertag 是长期、可检查的个人语义知识层。
2. 普通 Superchat Session 可以临时加载 Supertag Skill；Supertag Cowork 是独立的长期知识对话体验。
3. Cowork 面向整个知识库，不绑定当前 buffer、文件或概念。
4. Agent 使用 Supertag Query 作为主要只读逻辑接口，综合回答中引用具体 Org 原文。
5. 对话默认不写入正式知识；“记下来”等明确指令本身就是授权，Agent 立即写入并报告结果，不追加固定预览。
6. 写入时可以自动附上可确认的来源链接和相关原文。
7. Tag、Schema、字段、关系类型和 Semantic Edge 只能建议，用户确认后才能创建或修改。
8. 概念可以保留多条互相支持、补充或冲突的判断，后来的判断不覆盖旧判断。
9. 正式概念页不展示未经确认的推断、关联建议或对话草稿。
10. 只有 Cowork 自动维护独立的“最近一次对话总结”文件；新总结覆盖旧总结，普通 Skill 不更新。
11. 当前范围只处理个人知识语义层，不建设全量个人数据基础设施、向量库或新的 Agent Runtime。
12. 最近对话、外部来源、候选判断和正式笔记具有不同身份；只有用户明确保存的判断进入长期知识对话。
13. “记下来”先立即写入判断与可确认来源，随后才查询并提出关联建议；关联仍需用户单独确认。
14. 检索支持沿高层线索逐步展开原文、来源和上下文，不依赖用户预先维护完整关键词。
15. Zettelkasten 方法论只提供知识加工原则；产品不照搬 Roam 的固定层级，而使用 Supertag Query 动态组织原始节点。
